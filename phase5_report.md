CMD_IDENTIFY 0xEC to detect.\n- No explicit interrupt disable in disk.rs; input::recoger() disables interrupts around ring access.\n- sincronizar() for ATA issues CMD_FLUSH_CACHE (0xE7) after espera_libre; BIOS no-op.\n- ESTADO is SyncCell<Estado>; accessed via raw pointers, no lock held during I/O. leer/escribir copy base/origen values.\n\n## 3) Volume/FS state ownership\n- disk::ESTADO (SyncCell<Estado>): presente/sectores/origen/base/unidad/log_lba/log_sectores. Set in init/buscar_particiones.\n- fs::VOL (SyncCell<Option<Volumen>>): geometry, feature flags, etiqueta, desc table, per-group info, in-memory bitmaps (bm_bloques/bm_inodos), free counts. Accessed via vol() -> &mut Volumen (raw). Mounted by fs::montar() or fs::formatear() (which mounts). volcar() writes bitmaps/descriptors/superblocks/backups and calls disk::sincronizar().\n- fat32::LOG (SyncCell<Option<Log>>): log partition state and FAT chain; fat32::init() locates COMANDOS.LOG.\n- Follows sync.rs rule 2 (unique owner per task) for mutable globals; no cross-task holding across reschedule points.\n\n## 4) Paths that break if disk becomes async/callback-based\n- All disk APIs block/poll synchronously; fs loops over sectors/blocks assuming completion.\n- FS relies on volcar()+disk::sincronizar() for persistence and callers expect synchronous completion.\n- ATA wait loops call input::recoger() periodically (polling aid); async/IRQ model changes this completely.\n- FAT32 does RMW (read-modify-write) of sectors synchronously.\n- Mutable refs to VOL/ESTADO held across multiple disk ops with no locking; callbacks in different context would create reentrancy/aliasing issues.\n- Fixed buffers (BIOS BUF_BIOS/DAP) and direct pointer copies assume synchronous transfers.\n- listar_hasta/fs internals use reusable buffers filled synchronously.\n
